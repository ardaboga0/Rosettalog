# Rosettalog v0.1.0: first public release

Rosettalog helps SOC and detection engineering teams move off IBM QRadar. It translates QRadar
parsing logic and detection rules into content for other SIEMs, and it **tells you exactly what
did not make it**. Every translated element is FULL, PARTIAL or UNSUPPORTED, with a finding that
explains the difference, and you can check the results on sample data, locally or against real
engines.

This is an **alpha** release: usable, and honest about its gaps (below).

## What it does

- **Parsing migration.** QRadar **Log Source Extensions** → **Microsoft Sentinel** (KQL parser
  functions, ASIM names), **Splunk** (props.conf / transforms.conf, CIM names) and **Elastic**
  (ingest pipelines, ECS names). Java regexes are translated per engine (RE2, PCRE, Oniguruma),
  Joda-Time formats per target, and every semantic difference is reported.
- **Detection rules → Sigma.** Single-event rules, counters and sequences (Sigma correlations),
  building blocks and reference-data tests become Sigma rules. **pySigma** converts them to SPL,
  KQL, Lucene, ES|QL or EQL. Rosettalog never rewrites pySigma's output; where a pySigma backend
  refuses a construct or changes its meaning, the report says so.
- **Honest approximations.** A rule test Sigma cannot express is dropped only where that makes
  the rule broader, never narrower, and the generated `.yml` says so itself.
- **Verification.** Sample logs or events are run through the source semantics and the
  generated content, and the results are compared per field or per matching event. Opt-in
  (`--engine real`), the same comparison runs on pinned, local **Elasticsearch 9.5.4**,
  **Splunk 10.4.3** and the **Kusto emulator** containers.
- **Reports.** Markdown and JSON reports list every finding, the deployment scope of every
  setting (e.g. Splunk index-time vs search-time), and the unconfirmed QRadar assumptions the
  translation relies on.

## What it does not do (yet)

- **No QRadar rule-export parser yet.** Rules are written in the documented Rosettalog IR format
  (`*.ir.json`, see [docs/rules-ir-format.md](../rules-ir-format.md)). The parser waits for
  QRadar CE confirmation of the undocumented rule XML (open questions Q1-Q5).
- **No AQL translation.** It is planned as an integration point for existing translators, not
  an in-house translator.
- **Unconfirmed QRadar semantics.** Where IBM's documentation is silent, Rosettalog assumes: 16
  LSX assumptions and 9 rule assumptions, none observed on QRadar yet. One of them (A11,
  two-digit years) has documented evidence against it.
- **Downstream gaps.** Some pinned pySigma backends do not keep Sigma's meaning. Examples:
  Elasticsearch matches case-insensitive values case-sensitively, and Splunk/ES|QL correlations
  use fixed time buckets; see the
  [known gaps](../rules-support-matrix.md#known-downstream-gaps-observed).
- Not on PyPI; install from source.

The full list is in the [changelog](../../CHANGELOG.md#known-limitations).

## Install (from source)

Requires Python 3.11+.

```sh
git clone https://github.com/ardaboga0/Rosettalog.git
cd Rosettalog
git checkout v0.1.0
pip install .                        # parsing migration
pip install '.[sigma-backends]'      # + rules -> Sigma with pySigma conversion
# or with uv: uv sync --extra sigma-backends

rosettalog convert examples/acme_firewall/acme_fw.lsx.xml \
    --to sentinel --to splunk --to elastic --sourcetype acme:firewall \
    --samples examples/acme_firewall/samples.yaml -o out/
rosettalog convert examples/rules/acme_rules.ir.json --to sigma \
    -O sigma.pysigma_targets=splunk,kusto,esql --samples examples/rules/samples.yaml -o out-rules/
```

Open `out/report.md`, which lists what needs review and why.

## Help wanted: run the QRadar CE confirmation packs

Everything Rosettalog *assumes* about QRadar can be settled on **QRadar Community Edition**, and
each case takes only a few minutes:

- [LSX pack](../../examples/confirmation/README.md): 15 cases. Upload a tiny synthetic LSX,
  send a few syslog lines with `send.sh`, and note what QRadar extracts.
- [Rule pack](../../examples/confirmation-rules/README.md): 9 cases. Build a small rule in the
  UI, send the lines (the timed cases pace themselves), and note which events matched. **Please
  also export the rules:** that settles Q1-Q5 and unblocks the rule-export parser.

Report results in an issue with your QRadar version (template:
[RESULTS-TEMPLATE.md](../../examples/confirmation/RESULTS-TEMPLATE.md)). A single confirmed case
helps: the assumption's status changes, and every report shows it.
