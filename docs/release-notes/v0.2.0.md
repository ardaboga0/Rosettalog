# Rosettalog v0.2.0: Cortex XSIAM

This release adds **Cortex XSIAM** as a parsing target. QRadar Log Source Extensions now also
become XSIAM **Parsing Rules** and **Data Model Rules (XDM)**. As with every target, each element
is FULL, PARTIAL or UNSUPPORTED, and a finding explains any difference.

It is still an **alpha** release. Note especially that **the XSIAM output is
emulator-verified only** (see below).

## What's new

- **`--to xsiam`**: one `.xif` Parsing Rule per LSX, plus a `.model.xif` Data Model Rule.
  - The Parsing Rule is a single INGEST statement with `config case_sensitive = true`,
    `regexcapture()` per pattern, and match-group selection, fallbacks and event mappings done
    inline.
  - Timestamps are rebuilt from the captured components and parsed into `_time`.
  - The Data Model Rule maps fields to XDM only where the name is verified against the published
    XDM schema: IPs, ports (`to_integer`), MAC addresses (`arraycreate`), user name and event
    name. Everything else stays in the raw dataset with `FIELD_UNMAPPED`.
  - Options: `-O xsiam.vendor=… -O xsiam.product=… -O xsiam.target_dataset=…`.
- **XQL regex dialect.** Java regexes are translated to RE2 with named groups, as `regexcapture()`
  needs, and checked with real RE2.
- **XSIAM emulator.** `--samples` verification runs the generated rules through Rosettalog's
  interpreter of the documented XQL subset. It agrees with the Sentinel emulator on every
  shipped sample set; the one difference (literal backslashes) is reported.
- **Target-side assumptions.** Rosettalog has always tracked what it *assumes* about QRadar. It
  now does the same for XSIAM: five undocumented behaviours (X01-X05) sit in a registry, the
  findings that depend on them follow their status, and reports list the open global ones.
- **New finding `XSIAM_XDM_INTEGER_NORMALIZATION`.** A port modeled as an XDM Number loses its
  text form (`"0443"` becomes 443). This is now reported as a finding, not only as a
  verification difference.
- **Opt-in XSIAM tenant runner** (`--engine real --runner xsiam`). If you configure your own
  tenant, it sends the synthetic samples to your HTTP collector and reads the parsed and modeled
  values back through the XQL API. You install the generated rules yourself; no API exists for
  that.

## Limitations to know about

- **XSIAM output is emulator-verified only.** No local XSIAM engine exists. The output has been
  checked against Rosettalog's emulator, never on a tenant. The tenant runner is tested with
  stubbed HTTP only and **has never been run against a real tenant**.
- **Five XSIAM behaviours are unconfirmed** (X01-X05). They are inferred from Palo Alto's
  shipped content, not from documentation. Examples: what `regexcapture()` returns when nothing
  matches, and how backslashes in XQL string literals are read.
- **No XQL rule conversion.** The only pySigma XQL backend (pySigma-backend-cortexxdr) requires
  pySigma < 1.0 ([issue #20](https://github.com/7RedViolin/pySigma-backend-cortexxdr/issues/20))
  and has no correlations. Rosettalog documents this gap instead of writing its own renderer.
- **Unchanged from v0.1.0:**
  - The QRadar rule-export parser is pending (Q1-Q5).
  - There is no AQL translation.
  - 25 QRadar assumptions are unconfirmed.
  - The pySigma downstream gaps G0-G8 remain.
  - The package is not on PyPI.

The full list is in the [changelog](../../CHANGELOG.md#known-limitations).

## Install (from source)

Requires Python 3.11+.

```sh
git clone https://github.com/ardaboga0/Rosettalog.git
cd Rosettalog
git checkout v0.2.0
pip install .                        # parsing migration
pip install '.[sigma-backends]'      # + rules -> Sigma with pySigma conversion
# or with uv: uv sync --extra sigma-backends

rosettalog convert examples/acme_firewall/acme_fw.lsx.xml \
    --to sentinel --to splunk --to elastic --to xsiam --sourcetype acme:firewall \
    --samples examples/acme_firewall/samples.yaml -o out/
```

Open `out/report.md`, which lists what needs review and why.

## Help wanted: confirm XSIAM's (and QRadar's) behaviour

If you have an **XSIAM tenant**, the
[XSIAM confirmation pack](../../examples/confirmation/xsiam/README.md) takes a few minutes per
case:

1. Send the case's `sample.log` to an HTTP log collector with `send.sh`.
2. Paste `rule.xif` into the Parsing Rules editor and run **Simulate**.
3. Compare with `expected.yaml`.

Report the result in an issue with your XSIAM version. The
[QRadar CE packs](../../examples/confirmation/README.md) still need runs too, and a single
confirmed case helps: the assumption's status changes, and every report shows it.
